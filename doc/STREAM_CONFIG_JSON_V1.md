# StreamConfig JSON V1

The signaling backend stores `StreamConfig.payload` as opaque bytes. Robot and VR clients use the following JSON contract for media configuration.

Common gRPC fields:

| Field | Value |
|---|---|
| `schema_version` | `1` |
| `config_id` | Generated by the backend; never included in the JSON payload |

## Video (`prefix = 0x01`)

```json
{
  "codec": "H264",
  "width": 3840,
  "height": 1520,
  "fps": 30,
  "sps": "base64-encoded bytes",
  "pps": "base64-encoded bytes",
  "vps": "",
  "fov": {
    "hfov": 0.0,
    "vfov": 0.0,
    "dfov": 0.0
  }
}
```

- `codec` is `H264` or `H265`.
- `sps`, `pps`, and `vps` use standard Base64 without a data-URL prefix.
- `vps` is empty for H.264.
- `fov` is optional.

## Audio (`prefix = 0x04`)

```json
{
  "codec": "OPUS",
  "sample_rate": 48000,
  "channels": 1,
  "frame_duration_ms": 20,
  "samples_per_channel": 960,
  "bitrate_bps": 64000,
  "opus_inband_fec_enabled": true,
  "opus_dtx_enabled": false
}
```

All fields are required. A receiver must reject unsupported schemas, codecs, and configurations that do not match its playback capabilities.

## Exchange Flow

1. The publisher declares the prefix in its Publisher-local Stream Manifest.
2. The publisher calls `PublishStreamConfig` after the runtime configuration is ready.
3. The receiver calls `GetStreamConfig(publisher_session_id, prefix)` and validates the JSON.
4. StreamConfig is pull-based. There is no config event or ACK RPC.
